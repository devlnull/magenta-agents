Magenta 0.10.2 supports sessions that start in a parent folder of the repository (a workspace with many repositories).

- The guard applies the write rules of an agent to the path of the file in its repository. Before, an agent that owns `.magenta/checks/project.yaml` could not write `group/app/.magenta/checks/project.yaml` from a workspace session.
- The Stop and subagent hooks find the repository of the active task of the session. `start --repo <repository>` records it.
- Verify commands in a workspace folder use the one repository below it with an active task. Agents can run their git commands as `git -C <folder> <command>`.
- One limit stays: an agent cannot change the folder of a command, so project commands such as `./gradlew test` do not run in the repository from a workspace session. The checks still run there. For all agent commands, start the session in the repository.

## Upgrade

1. `claude plugin marketplace update magenta-marketplace`, then `claude plugin update magenta@magenta-marketplace`.
2. Restart Claude Code. A session that started before the update keeps the old hooks.
3. Check the version: `claude plugin list`, or `/plugin` in Claude Code.
