Magenta 0.10.3 closes shell bypasses of the guard.

A QA lens ran `docker compose exec ... php -r` with an encoded `;` to read a file. A broad pattern in `.magenta/policy.json` allowed the `docker` command, and the PHP code was outside the write and secret rules.

- The guard blocks inline code for interpreters, also behind a wrapper such as `docker compose exec app`: `php -r`, `python -c`, `node -e`, `sh -c`, `bash -lc`, `perl -e`, `ruby -e`, `deno eval`, `pwsh -Command`, `cmd /c`, and more.
- The guard blocks shell syntax that bash expands but the guard does not see: `$` outside single quotes (variables, `$@`, encoded characters such as `$'\x3b'`) and brace expansion such as `{a,b}`.
- The guard blocks a wildcard word that gives a secret path, for example `.e?v`.
- Check your `.magenta/policy.json`: write each shell pattern as narrow as possible, for example `docker compose exec -T app php artisan test*`, not `docker compose exec *`.

## Upgrade

1. `claude plugin marketplace update magenta-marketplace`, then `claude plugin update magenta@magenta-marketplace`.
2. Restart Claude Code. A session that started before the update keeps the old hooks.
3. Check the version: `claude plugin list`, or `/plugin` in Claude Code.
