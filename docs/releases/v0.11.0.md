Magenta 0.11.0 makes the guard less strict for code, and fixes the problems found in real tasks.

## The guard lets the agents change the code

The new default mode `standard` lets all agents change the code. Git, the approved checks, the locks, and the review find mistakes. The guard still protects the process and your computer:

- The files in `.magenta/` keep their owners. Makers cannot write locked tests.
- The human-only files (`policy.json`, the approvals, the verify state, `.claude/`, `.git/`) and the secrets stay blocked.
- The shell runs any simple command, except dangerous commands: push, merge, rebase, reset `--hard`, stash, restore, `rm`, deploy, publish, `gh`, `ssh`, `sudo`, and global installs.

For the former rules (file ownership and a shell allowlist), add `{"guard": "strict"}` to `.magenta/policy.json`, or set `MAGENTA_GUARD=strict`.

## Fixes

- A session in an application with the Magenta repository in a subfolder (for example `vendor/`) uses the rules of that repository. Before, the Engineer could write its `policy.json` and checks.
- The fingerprint includes the current content of the locked tests, also in a folder that git ignores. `fingerprint.include` in `.magenta/policy.json` adds other ignored files.
- Verify commands in an application folder find the Magenta repository in `vendor/`.
- The guard blocks container mounts outside the project, the Docker socket, and `--privileged`. `mounts` in `.magenta/policy.json` allows more folders.
- Checks get `MAGENTA_REPO`. `list` and the approval dialog show a note for a pipeline without `pipefail`.
- Verify keeps the last 30 run folders, with UTC names. The conductor writes the review results and the decisions of the human in the work item.

## Upgrade

1. `claude plugin marketplace update magenta-marketplace`, then `claude plugin update magenta@magenta-marketplace`.
2. Restart Claude Code. A session that started before the update keeps the old hooks.
3. Check the version: `claude plugin list`, or `/plugin` in Claude Code.
